# 3D Viewer Canvas Artifact Spec

**Project:** Canvas Artifact System  
**Artifact:** 3D Model Viewer  
**Target implementer:** Codex / Cursor Agent  
**Primary stack:** React, TypeScript, Three.js, React Three Fiber  
**Primary artifact format:** `.glb` / `.gltf`  
**Secondary formats:** `.obj`, `.fbx`, `.stl`, `.ply`, `.ifc`  
**Date:** 2026-07-03

---

## 1. Purpose

Create a reusable **3D Viewer Canvas Artifact** that allows users to import, preview, inspect, annotate, and manage 3D files inside the Canvas system.

The artifact should behave like other Canvas artifacts:

- it can appear as a compact card on the canvas;
- it can open into an inline viewer;
- it can expand into a focused full-screen artifact workspace;
- it stores metadata, source files, canonical converted files, annotations, generated thumbnails, and relationships to other artifacts;
- it can be referenced by agents, tools, workflows, and future design/studio systems.

This is not initially intended to be a full BIM coordination platform. It should begin as a general-purpose 3D artifact viewer with a clear path toward BIM support.

---

## 2. Design Principle

The system should treat a 3D model as a **living Canvas artifact**, not merely as a file preview.

A model may be:

- uploaded by the user;
- generated by an AI model;
- derived from another artifact;
- converted from another format;
- annotated;
- inspected;
- branched;
- versioned;
- connected to a workflow, agent, or exploration path.

The viewer should preserve both the **visual state** and the **artifact state**.

## 3. Recommended Library Stack

### 3.1 Default Viewer Stack

Use:

```bash
npm install three @react-three/fiber @react-three/drei three-stdlib
```

| Library | Purpose |
|---|---|
| `three` | Core WebGL 3D engine |
| `@react-three/fiber` | React renderer for Three.js |
| `@react-three/drei` | Useful viewer helpers: orbit controls, environment, loaders, bounds, HTML labels |
| `three-stdlib` | Additional loaders and utilities |

### 3.2 Format Support

Use Three.js loaders for common formats:

| Format | Loader | Priority |
|---|---|---|
| `.glb` / `.gltf` | `GLTFLoader` | High |
| `.obj` | `OBJLoader` | Medium |
| `.fbx` | `FBXLoader` | Medium |
| `.stl` | `STLLoader` | Medium |
| `.ply` | `PLYLoader` | Low / optional |
| `.ifc` | `web-ifc-three` or later `xeokit` | Later stage |

### 3.3 BIM-Specific Future Stack

For IFC / BIM, support should be staged.

#### Early BIM support

```bash
npm install web-ifc web-ifc-three
```

Use this when Canvas needs simple IFC import, object selection, and metadata access while staying close to the Three.js/R3F viewer.

#### Later serious BIM support

Evaluate `xeokit` for large IFC, federated models, model tree, sections, issue workflows, and `.xkt` conversion.

Do not make xeokit the default viewer in the first implementation. Treat it as a possible specialized BIM artifact viewer.

## 6. Storage Model

### 6.1 File Storage

Store files outside the main database, using object storage or local file storage depending on current Canvas setup.

Recommended structure:

```txt
/artifacts/{artifactId}/source/{originalFilename}
/artifacts/{artifactId}/canonical/model.glb
/artifacts/{artifactId}/preview/thumbnail.png
/artifacts/{artifactId}/metadata/model.json
```

### 6.2 Database Storage

Store the artifact record in the existing Canvas artifact table.

Minimum fields:

| Field | Purpose |
|---|---|
| `id` | Artifact ID |
| `type` | `artifact.3d-model` |
| `name` | User-facing name |
| `status` | Processing state |
| `source_file_url` | Original uploaded file |
| `canonical_file_url` | Converted web-friendly file |
| `thumbnail_url` | Canvas preview image |
| `metadata_json` | Bounds, counts, units, etc. |
| `viewer_state_json` | Camera, display mode, toggles |
| `annotations_json` | Marker data |
| `relationships_json` | Links to other artifacts |
| `created_at` | Created timestamp |
| `updated_at` | Updated timestamp |

### 6.3 Canonical Format Rule

Use this rule:

> Preserve the original uploaded file, but store a web-optimized canonical file where possible.

For MVP:

- if the source is `.glb` or `.gltf`, it can be canonical directly;
- if the source is `.obj`, `.fbx`, `.stl`, or `.ply`, display directly first;
- later add backend conversion to `.glb`;
- if the source is `.ifc`, handle through a BIM-specific import path later.

## 9. Import Flow

### 9.1 User Flow

1. User drags a 3D file into Canvas.
2. Canvas detects supported file format.
3. Artifact record is created with status `uploading`.
4. File is stored.
5. Artifact status becomes `processing`.
6. System attempts to load model in hidden or inline scene.
7. Metadata is computed.
8. Thumbnail is generated.
9. Artifact status becomes `ready`.
10. Card appears on canvas.

### 9.2 Supported Extension Detection

Implement:

```ts
export function detectThreeDFormat(filename: string): ThreeDFileFormat | null {
  const ext = filename.split(".").pop()?.toLowerCase();

  switch (ext) {
    case "glb": return "glb";
    case "gltf": return "gltf";
    case "obj": return "obj";
    case "fbx": return "fbx";
    case "stl": return "stl";
    case "ply": return "ply";
    case "ifc": return "ifc";
    default: return null;
  }
}
```

### 9.3 Failure States

Handle failures explicitly:

| Failure | User-facing status |
|---|---|
| Unsupported extension | Unsupported file type |
| File too large | File exceeds viewer limit |
| Loader failed | Could not load model |
| Texture missing | Model loaded with missing textures |
| Browser memory issue | Model too heavy for inline preview |
| IFC not enabled | IFC support not installed yet |

Do not silently fail.

## 10. Model Loading

### 10.1 Loader Abstraction

Create one loader entry point.

```ts
export async function loadThreeDModel(params: {
  url: string;
  format: ThreeDFileFormat;
}): Promise<THREE.Object3D> {
  switch (params.format) {
    case "glb":
    case "gltf":
      return loadGltf(params.url);
    case "obj":
      return loadObj(params.url);
    case "fbx":
      return loadFbx(params.url);
    case "stl":
      return loadStl(params.url);
    case "ply":
      return loadPly(params.url);
    case "ifc":
      throw new Error("IFC support not enabled in MVP");
    default:
      throw new Error("Unsupported 3D format");
  }
}
```

### 10.2 GLB/GLTF Loader

Use `GLTFLoader`.

Requirements:

- preserve materials;
- preserve textures;
- support embedded GLB;
- fit loaded model to view;
- compute bounds;
- extract animation count if present.

### 10.3 STL Loader

STL has geometry only. Apply a default material.

### 10.4 OBJ/FBX Loader

Support basic display. Materials may be incomplete. Treat this as compatibility import, not canonical artifact behavior.

## 11. Metadata Extraction

After model load, compute:

- bounding box;
- center;
- size;
- mesh count;
- material count;
- approximate vertex count;
- approximate triangle count;
- texture count where available;
- whether animations exist;
- whether cameras/lights exist;
- estimated complexity.

Example:

```ts
export function computeModelStats(object: THREE.Object3D): ThreeDModelMetadata {
  const box = new THREE.Box3().setFromObject(object);
  const size = new THREE.Vector3();
  const center = new THREE.Vector3();
  box.getSize(size);
  box.getCenter(center);

  let meshCount = 0;
  let vertexCount = 0;
  let triangleCount = 0;
  const materials = new Set<string>();

  object.traverse((child) => {
    if ((child as THREE.Mesh).isMesh) {
      meshCount++;
      const mesh = child as THREE.Mesh;
      const geometry = mesh.geometry as THREE.BufferGeometry;

      const position = geometry.getAttribute("position");
      if (position) vertexCount += position.count;

      if (geometry.index) {
        triangleCount += geometry.index.count / 3;
      } else if (position) {
        triangleCount += position.count / 3;
      }

      const material = mesh.material;
      if (Array.isArray(material)) {
        material.forEach((m) => materials.add(m.uuid));
      } else if (material) {
        materials.add(material.uuid);
      }
    }
  });

  return {
    bounds: {
      min: [box.min.x, box.min.y, box.min.z],
      max: [box.max.x, box.max.y, box.max.z],
      size: [size.x, size.y, size.z],
      center: [center.x, center.y, center.z],
    },
    meshCount,
    vertexCount,
    triangleCount,
    materialCount: materials.size,
    estimatedComplexity:
      triangleCount > 2_000_000 ? "very_high" :
      triangleCount > 500_000 ? "high" :
      triangleCount > 100_000 ? "medium" :
      "low",
  };
}
```

## 12. Viewer State

The viewer must store state so that the artifact reopens as the user left it.

Persist:

- camera position;
- camera target;
- display mode;
- grid visibility;
- axes visibility;
- bounds visibility;
- annotation visibility;
- selected object ID later;
- clipping planes later.

Save state on:

- user clicks “Save View”;
- artifact closes;
- periodic debounce while viewing if already supported by Canvas.

Avoid writing to the DB on every camera movement without debouncing.

## 14. Performance Requirements

### 14.1 MVP Targets

The viewer should comfortably handle:

- `.glb` files under 50 MB;
- triangle count under 500k;
- a single active inline viewer at a time;
- multiple cards with thumbnails only.

### 14.2 Avoid Memory Problems

Rules:

- do not render every 3D card as a live WebGL scene;
- use thumbnails for cards;
- only mount the 3D scene when opened;
- unmount and dispose resources when closed;
- call geometry/material/texture disposal on unmount;
- lazy-load heavy loaders;
- show warning for very heavy models.

### 14.3 Disposal Helper

Implement safe cleanup.

```ts
export function disposeObject3D(object: THREE.Object3D) {
  object.traverse((child) => {
    const mesh = child as THREE.Mesh;
    if (mesh.geometry) mesh.geometry.dispose();

    const material = mesh.material;
    if (Array.isArray(material)) {
      material.forEach(disposeMaterial);
    } else if (material) {
      disposeMaterial(material);
    }
  });
}

function disposeMaterial(material: THREE.Material) {
  Object.values(material).forEach((value) => {
    if (value && typeof value === "object" && "dispose" in value) {
      try {
        value.dispose();
      } catch {
        // ignore texture disposal errors
      }
    }
  });
  material.dispose();
}
```


### 19.2 Model Loader Skeleton

```tsx
import { useLoader } from "@react-three/fiber";
import { GLTFLoader } from "three-stdlib";

export function ThreeDModelLoader({ artifact }) {
  const url = artifact.canonicalFile?.url ?? artifact.sourceFile.url;
  const format = artifact.canonicalFile?.format ?? artifact.sourceFile.format;

  if (format !== "glb" && format !== "gltf") {
    return null;
  }

  const gltf = useLoader(GLTFLoader, url);
  return <primitive object={gltf.scene} />;
}
```

This is intentionally minimal. Production code should route through the loader abstraction and add cleanup, progress, error boundaries, metadata extraction, and format branching.

## 21. Security and Safety

3D files are user-uploaded files and should be treated as untrusted.

Requirements:

- validate extension;
- enforce max file size;
- do not execute arbitrary scripts from model files;
- sanitize filenames;
- isolate file storage paths;
- handle loader errors safely;
- avoid exposing local filesystem paths;
- prevent model files from triggering app crashes through uncontrolled memory use.

Recommended MVP limits:

| Limit | Value |
|---|---|
| Max upload size | 100 MB |
| Preferred size | under 50 MB |
| Triangle warning | over 500k |
| Triangle danger warning | over 2M |
| Active inline viewers | 1 |

## 23. Acceptance Criteria

The implementation is acceptable when:

1. A user can drag a `.glb` file into Canvas and create a `artifact.3d-model` artifact.
2. The artifact appears as a card with a thumbnail or fallback preview.
3. The user can open the model in an inline viewer.
4. The user can orbit, pan, zoom, reset, and fit the model.
5. The system computes and stores basic metadata.
6. The user can open a full artifact viewer.
7. The viewer state can be saved and restored.
8. The viewer disposes resources when closed.
9. Unsupported or failed imports show clear errors.
10. The schema leaves room for annotations, relationships, conversions, and future BIM support.

---

## 24. Important Architectural Decision

The first version should not overfit to BIM.

Use this hierarchy:

```txt
3D Model Artifact
  ├─ general mesh / GLB viewer now
  ├─ generated asset viewer now
  ├─ projection-box / spatial prototype viewer soon
  └─ BIM / IFC viewer later
```

This keeps Canvas flexible for:

- AI-generated 3D assets;
- architectural massing;
- projection studies;
- product concepts;
- spatial diagrams;
- imported design models;
- future BIM workflows.
